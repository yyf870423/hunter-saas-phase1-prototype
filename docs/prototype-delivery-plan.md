# Hunter SaaS 阶段一原型实施与审核计划

## 1. 实施目标

本原型依据《Hunter 阶段一完整可交互原型规划》和已审批的 **WorkBuddy × Vercel AI 任务空间**视觉方向实现。交付物必须让产品、UX、研发和运营人员在不依赖口头解释的情况下，完成六条端到端用户故事，检查 45 个用户端页面、15 个运营端页面及其正常、异常和恢复路径。

## 2. 实施顺序

### 阶段 A：业务与数据底座

1. 冻结页面编号、路由、对象关系和六条用户故事。
2. 建立统一演示世界、跨页状态和浏览器本地持久化。
3. 审核门禁：同一公司、岗位、候选人、任务和数量在所有页面一致；操作后关联页面同步变化。

### 阶段 B：视觉与公共组件

1. 建立浅色、深色 Token、桌面与移动断点、本地 SVG 资产。
2. 完成导航、按钮、输入、单选、多选、多级选择、日期、表格、分页、标签、Tooltip、Toast、Modal、Drawer、Sheet、上传、进度和时间线。
3. 审核门禁：没有用户可见的浏览器默认控件；没有 Icon 包、Icon Font、Emoji、Unicode 图形、外部图形 CDN 或位图替代；组件具备正常、Hover、Focus、Loading、Empty、Error、Disabled 和权限受限状态。

### 阶段 C：六条用户故事骨架

按以下顺序串联端到端路径：

1. 招聘信号进入客户开发，形成招聘机会和岗位。
2. 岗位招聘召回候选人，审核匹配并人工推进。
3. 人才摸排建立公司、方向、角色、人物和关系成果。
4. 候选人收到新资料后更新档案、查重并局部重新匹配。
5. 外部联系进入等待，收到异步回复后继续原任务。
6. 任务异常、平台登录失效、恢复、额度和订阅到期处理。

审核门禁：每条故事都可以从入口走到业务结果；等待不会表现为持续消耗；人工承诺动作不能被 Agent 自动完成；中断恢复不创建重复用户任务。

### 阶段 D：完整用户端

1. 完成 U01–U06 访问、工作台与全局框架。
2. 完成 U07–U12 四类业务主线。
3. 完成 U13–U16 支线任务与信号。
4. 完成 U17–U34、U45 业务资产、沟通与候选人岗位推进。
5. 完成 U35–U44 数据进入、账户、授权、平台、订阅和数据支持。

审核门禁：页面入口、返回、关联对象和操作去向完整；列表保留筛选与分页；详情返回后恢复位置；所有可见命令有真实状态变化或页面跳转。

### 阶段 E：完整运营端

完成 O01–O15 的申请审核、工作空间、订阅、用量、任务、错误、依赖、诊断、公告和审计。

审核门禁：运营端只展示脱敏运行信息和必要账号元数据，不出现用户输入、输出、附件、候选人、岗位或公司业务正文；权限不足时从结构中移除敏感内容。

### 阶段 F：多端与异常

1. 检查 1440×900、1366×768、1180×820、820×1180 和 390×844。
2. 补齐 Loading、Empty、Error、Disabled、Permission-limited、风险、警告、成功、暂停和恢复。
3. 检查键盘访问、焦点恢复、Reduced Motion、文本溢出、Sticky 和浮层遮挡。

审核门禁：移动端功能不减少；表格转信息列表；固定区域不遮挡正文；任何文字、按钮和浮层不越界。

### 阶段 G：自动化审核与发布

1. 路由烟测覆盖 60 个页面。
2. Playwright 覆盖六条用户故事、关键错误分支和跨页状态联动。
3. 截图检查桌面、iPad 和 iPhone；与 WorkBuddy moodboard 的 Token、密度、层级和动效基线对照。
4. Review 发现问题后修复并重复执行，直到没有已知阻塞问题。
5. 发布公开 GitHub 仓库，通过 GitHub Actions 部署 Pages，并在线复测关键故事。

## 3. 页面审核顺序

页面审核不按编号机械进行，而按用户任务依赖推进：

1. `登录 → 首次开通 → 工作台 → 新建主线`。
2. `信号 → 客户开发 → 公司/联系人/机会 → 岗位`。
3. `岗位招聘 → 任务 → 候选人 → 沟通 → 候选人岗位推进`。
4. `人才摸排 → 摸排资产 → 人物关系证据 → 支线任务`。
5. `候选人求职 → 新资料 → 查重 → 局部重新匹配`。
6. `数据进入 → 解析确认 → 正式资产`。
7. `授权 → 平台 → 用量 → 订阅 → 数据与支持`。
8. `运营申请 → 工作空间 → 权益 → 任务故障 → 诊断 → 审计`。

## 4. Review 记录方式

每轮 Review 记录以下内容：页面编号、视口、用户目标、触发动作、预期状态、实际状态、视觉差异、交互差异、严重度、修复提交和复测结果。阻塞问题包括：流程断点、错误写入、权限泄露、不可恢复、页面空白、控件失效、严重遮挡和与审批视觉方向明显不符。

## 5. 完成标准

1. 45 个用户端页面和 15 个运营端页面均可访问。
2. 六条用户故事和 21 条操作流程有自动化覆盖或明确的人工截图检查记录。
3. 所有主要命令、表单、筛选、分页、上传、拖拽、Modal、Drawer、Toast、删除和恢复均可交互。
4. 用户端与运营端权限边界明确，演示数据一致且可信。
5. 五种目标视口不存在横向溢出、遮挡、空白画布和不可触达操作。
6. GitHub Actions 构建成功，公开 Pages 能打开并完成关键故事。
