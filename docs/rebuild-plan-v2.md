# Hunter SaaS 阶段一原型 v2 重构执行计划

本文件是《Hunter 阶段一完整交互原型重构方案 v2》的工程执行映射。方案以 Hunter 当前业务资产结构为事实来源，以 WorkBuddy × Vercel 的已选视觉方向为基础，不复用旧原型中简化的资产结构和静态完整对话。

## 一、页面重构范围

1. 全局应用框架：默认收起 SVG 导航、Logo、用量环、通知、全局搜索和创建入口。
2. 工作台：需要处理、正在运行、重要变化、业务主线和近期资产形成清晰主次关系。
3. 四类业务主线：从首条用户输入开始流式推进，支持选择确认、自然语言、文件和右侧预览。
4. 独立任务：保留任务状态、运行过程、暂停恢复、检查点、结果文件和回到来源主线。
5. 业务资产：公司、联系人、招聘机会、岗位、候选人、人才摸排、论文、专利。
6. 招聘推进：独立人岗匹配结果、候选人岗位推进详情、泳道图与岗位流程编辑。
7. 数据进入、设置与运营后台：保留现有页面范围，统一新的应用框架和公共组件。

## 二、核心交互映射

| 用户动作       | 页面入口        | 正常结果                                       | 异常或边界                       |
| -------------- | --------------- | ---------------------------------------------- | -------------------------------- |
| 搜索候选人     | 候选人列表      | 空格或逗号拆词，显示命中结果                   | 空结果；仅命中原始简历提示       |
| 启动候选人补全 | 候选人详情      | 创建任务并打开业务主线或任务详情               | 资料不足时阻止并说明缺少项       |
| AI 解析岗位    | 岗位详情        | 输入补充说明，创建岗位解析任务                 | 必填缺失；运行失败；结果待审核   |
| 编辑岗位流程   | 岗位详情        | 增删、重命名、拖拽阶段并保存                   | 最少阶段、稳定阶段类型不可破坏   |
| 推进候选人     | 岗位泳道        | 拖拽后填写备注，记录时间线                     | 不允许的跨阶段移动；取消后回原位 |
| 人岗匹配       | 岗位详情        | 新增或全量匹配，进入独立结果页                 | JD 分析中；模型不可用；无结果    |
| 编辑与删除资产 | 各资产详情/列表 | 保存后同步列表与关联页；删除后返回列表         | 必填、重复、存在关联、删除确认   |
| 主线确认       | 对话            | 预设选项或自然语言均形成用户消息并继续流式输出 | 模糊输入追问；大批量转完整审核   |
| 查看大结果     | 对话            | 右侧预览 Markdown 文件，或打开独立稳定业务页   | 文件生成失败；重新生成；下载失败 |

## 三、中间结果场景分配

| 场景           | 主要覆盖结果                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 客户开发主线   | 目标理解、需求澄清、搜索策略、来源证据、证据冲突、公司联系人草稿、招聘信号、招聘机会、沟通草稿、发送结果、外部回复、支线任务 |
| 岗位招聘主线   | 岗位解析、搜索条件、候选池、身份查重、人岗匹配、联系授权、平台阻塞、无结果、运行失败、部分完成                               |
| 人才摸排主线   | 组织草图、人物线索、论文专利线索、关系路径、覆盖空缺、支线建议、生成报告                                                     |
| 候选人求职主线 | 外部回复、简历附件、资料差异、身份冲突、影响分析、局部重新匹配、沟通建议                                                     |
| 独立任务       | 运行失败、重试、登录、预算、门禁修正、无结果、诊断下载                                                                       |

Review 首页增加 31 类中间结果覆盖索引，每一项定位到上述真实场景，不创建脱离业务的组件展览。新增结果类型时，必须先补入覆盖索引、对应业务数据和交互测试，不能只新增一个通用卡片。

## 四、公共组件与页面映射

- `CompactNav`：全部用户端页面。
- `UsageRing`：导航底部和用量详情。
- `AssetListPage`：八类业务资产列表。
- `AssetDetailHeader` + `DetailTabs`：业务资产详情。
- `ConversationShell` + `StreamingMarkdown` + `ChoicePrompt`：业务主线与任务。
- `PreviewPane` + `MarkdownArtifact`：大文本、文件、证据和任务详情。
- `MatchReviewPage`：岗位人岗匹配结果。
- `PipelineBoard` + `StageEditor`：岗位推进。

## 五、Review 顺序

1. 数据结构 Review：跨页对象、数量、名称和关联一致。
2. 框架 Review：默认收起导航、工作区宽度和移动端导航。
3. 资产 Review：逐类对照 Hunter 模板和真实页面字段。
4. 会话 Review：四类主线逐步推进、流式、选择和自然语言路径。
5. 结果 Review：对话内、右侧 Markdown、独立匹配页三类结果均可用。
6. 自动化 Review：路由、交互、响应式、字号和截图全部通过。
